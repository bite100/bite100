## 2. 本站现状骨架的问题（对照代码实查）

1. **主导航是桌面式胶囊分段控件，躺在页面流中部**（`Navigation.css`：横向滚动的 pill 组）。手机上要先滚过品牌头和整张连接/钱包卡才够得到导航，且导航不固定、切页后位置漂移——与所有主流交易 App 的「底部固定标签栏」范式相反。这是 Ren 说「骨架难看」的第一来源。
2. **顶栏占位过大**：品牌头（34–40px 图标 + 两行文字）+ 连接条/钱包信息整卡 + 离线横幅都堆在内容之前，首屏真正内容（行情/余额）被推到第二屏。
3. **交易页是桌面三列网格在手机上塌陷成单列**（`TradeScreen.css`：`chart rail side / tabs rail side` 网格，移动端按 area 顺序堆叠）：图表 → 挂单表 → 盘口 → 成交 → 下单的顺序由网格塌陷决定，下单面板沉到很深处，不是按「看盘→看簿→下单→管单」的手顺序设计。
4. **没有统一的页面分工**：五页各用各的堆叠方式（页头大标题 + 卡片流），没有「头条区 / 内容区 / 固定操作条」的共同语言；表单页（桥）的主按钮随页面流滚走，拇指够不到。
5. **列表组织不统一**：有的行是整卡、有的行是卡内细线行，没有币安式「卡内细线分行」的统一密度语言。
6. **底部无占位概念**：内容滚到底与浏览器手势区贴边，没有为固定栏预留安全区 padding。

## 3. 设计方案总览

### 3.1 全局框架（所有页面共用）

```
┌──────────────────────────────────┐
│ 顶栏（固定，48px）                │ 品牌字标 B + 当前栏目名 | 链 chip（圆点+链名） 钱包 chip
├──────────────────────────────────┤
│ 页头（仅二级页）：标题 + 一句说明  │ 资产/桥/治理/数据有；交易页由交易对头条充当页头
│ 内容区（滚动）：卡片流，间隔 12px  │ 页面左右内边距 12px（卡内 16px）
│                                  │
│ （桥页）固定操作条：费用摘要+主按钮 │ 位于标签栏之上，顶边细线
├──────────────────────────────────┤
│ 底部标签栏（固定，56px + 安全区）  │ 交易 / 资产 / 跨链桥 / 治理与贡献 / 数据
└──────────────────────────────────┘
```

- **顶栏**：48px 固定。左：品牌字标块 + 当前栏目名；右：链切换 chip（现状 `ChainSwitcher` 收缩为 chip 形态）+ 钱包状态 chip（未连接=「连接钱包」按钮；已连接=短地址）。现「连接条/钱包卡」整卡取消：未连接时的完整说明移到各页的连接空态里（现 `ConnectGate` 模式保留），账户详情（连接方式、ETH 余额、断开）收进「资产」页头条卡的展开行。离线横幅保留在顶栏下方。
- **底部标签栏**：56px + `env(safe-area-inset-bottom)`，白底 96% + 顶边 1pt 细线（本站 `--b100-border`），图标 22px + 标签 10–11px 恒显示；选中态=本站强调色 `#FF007A`（图标+标签），未选中=`--b100-text-3`。内容区底部 padding = 标签栏高 + 安全区 + 12px，滚到底不被遮。
- **内容区骨架语言**：卡片=白底、24px 圆角、轻阴影（本站既有 token）；卡内列表一律**细线分行**（1pt `--b100-border`），不再一行一卡；数字一律等宽右对齐（第 28 轮规则）；分段控件与文字页签沿用第 13/28 轮的胶囊/下划线两种现成形态。
- **桌面放大（同一套骨架，不是两套站）**：≥1024px 时——底部标签栏变身为顶栏下方的横排导航条（同一个 `Navigation` 组件换定位，选中态样式不变）；内容最大宽度放到 1200px；交易页恢复三列网格（第 28 轮现状布局：图表+页签表 / 盘口+成交轨 / 下单栏），其余页表单区改双列（资产存/提双列为现成形态）。断点以下（<1024px）一律走移动骨架，含平板竖屏。

### 3.2 信息架构：五栏目 → 底部标签栏映射

| 标签 | 图标 | 对应现有分区（Tab） | 内部首屏 | 理由 |
|---|---|---|---|---|
| 交易 | K 线 | `trade`（Dashboard + 完整订单簿） | 交易对头条 | 核心页，排第一位（最左，拇指热区）；与币安把 Trade 放核心位同理 |
| 资产 | 钱包 | `assets`（Vault 存提 + **做市金库卡位**） | 余额头条卡 | 资金入口，紧随交易；币安 Wallets/Assets 同理 |
| 跨链桥 | 双向箭头 | `bridge`（CrossChainBridge） | 从/到链卡片 | 独立任务型页面，单独一栏便于直达 |
| 治理与贡献 | 盾牌✓ | `govern`（治理 / 贡献奖励两子页签） | 子页签 + 提案列表 | 低频但需固定入口；标签用全称「治理与贡献」（5 字 × 11px ≈ 58px < 单栏 78px，可容纳，不缩写以免与页内标题不一致） |
| 数据 | 柱状图 | `data`（RewardPoolInfo + 合约地址） | 奖励池头条统计 | 公开数据，无需钱包；排末位 |

映射与现有 `Tab` 类型、URL 参数（`?tab=` 与旧链接兼容表）**一一对应、零变更**——本方案只改导航的呈现位置与形态，不改信息架构本身，旧链接与 `governSub` 子页签逻辑全部保留。

- **导航扩展预案（抽屉模式备忘，本轮不采用；结构参考 HY 的栏目组织方式，视觉以币安为准）**：Hyperliquid 移动端是「底部 3 页签（市场 / 交易 / 账户）+ 汉堡抽屉装全部栏目」——抽屉内含交易 / 投资组合 / 赚取 / 金库 / 质押 / 推荐 / 排行榜及工具类（测试网 / 浏览器 / 子账户 / API / 积分 / 公告 / 统计）。本站五栏按上表映射定案，不改；预案记在此处：将来栏目继续增多（公告、API 文档、排行榜等工具类）致五栏放不下时，优先把工具类栏目收进顶栏抽屉，不加第六个底栏格子、不缩短栏目标题。

### 3.3 逐页骨架规格

#### 交易页（核心页，v2 按真机截图重做，演示图 ①②）

### 12.3 跨链桥 WTKA 准备区（新增演示图 r31-demo-bridge-prep.png）

- **落点**：桥页通道选择卡**下方**、风险提示条**上方**新增「准备区」卡；仅当选中 **CCIP 或 Wormhole** 时展开——这两条通道转移的是包裹代币 WTKA（第 19 轮 1:1 包裹/解包的胶水代币）；LayerZero（直连 TKA）与极速到账不出现此区。此前准备动作埋在桥流程内部，本节起显式成区。
- **内容**：四行账目（我的 TKA（Vault 可用）/ 我的 WTKA 余额 / 本次转移需要 WTKA / 还差）→ 包裹数量输入（默认按差额预填）→「包裹 TKA → WTKA」按钮 → 解包行（WTKA → TKA；到账后在目标链选任一 CCIP/Wormhole 通道时同区可见）。
- **状态流（定死）**：未选通道（固定操作条禁用：「先选择通道，再发起转移」）→ 选 CCIP/Wormhole 且 WTKA 不足（准备区展开、状态丸「待包裹」、固定条禁用：「先完成包裹，再发起转移」）→ 包裹交易上链确认（准备状态「已就绪」、固定条可用）→ 点发起 → 确认框复述费用与风险（现机制不变）→ 钱包批准。WTKA 余额已足额时准备区只显示「已就绪」一行，不必包裹；切换到 LayerZero/极速到账时准备区收起，已包裹的 WTKA 不受影响。
- **口径**：包裹是独立链上交易（在钱包中确认），1:1 无损耗，桥费另计；演示图为 CCIP 已选定 + 待包裹一态（其余三条通道文案与桥页主演示逐字一致）。
