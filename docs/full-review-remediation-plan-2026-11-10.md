## 第 61 轮·治理加固（合约轮）

1. **活跃集快照来源受控**（P1-01）：createProposal / createMultiStepProposal 不再接受调用者自带 merkleRoot/activeCount。快照改由治理管理员（现阶段 owner，后续多签）按周期发布并上链固定，提案只能引用已发布的快照编号。此步同时补上老问题“活跃集无人产生”：快照的产生者就是发布者，输入清单来自贡献计量（离线 CLI 输出 + 发布者签认）。
   - 关于 ChatGPT 建议的 OZ Governor 迁移：Governor 的投票权模型（ERC20Votes 检查点）与本项目 Merkle 活跃集模型不同构，硬迁等于重做治理模型。本轮**不迁**，先堵洞；迁移与否在本轮收尾时出一个小调研（适配层成本 vs 收益）再由 Ren 定。
2. **贡献证明换可信证明者**（P1-02）：submitProof/Ex 系列改验**独立统计者**的 EIP-712 签名（绑 chainId、period、account、指标、nonce、截止时间），统计者 = 现有离线计量 CLI 的签名化版本，私钥与提交者分离；周期结束冻结评分，事后修改只走带事件记录的纠错流程（其 P2-05 一并关闭）。
3. **加权投票二选一**（P2-03）：本轮先**摘除假功能**——voteWithWeight 若不能真计票就下线入口并同步前端文案（功能变更带说明的老规矩）；真加权计票等治理模型定案（见第 1 条调研）后再议。
4. 顺带：contracts/src/MerkleProof.sol 换 OpenZeppelin MerkleProof（同文件域、低风险，叶子哈希口径已有兼容声明，换完跑全量治理测试回归）。

验收：forge 全量 + 针对三条的攻击回归测试（自选快照提案应失败、自签证明应失败、权重事件不得冒充计票结果）。

## 第 62 轮·nonce 语义（先调研，后定案）

- 背景裁定：顺序水位耦合**成立**（高 nonce 先成交会让低 nonce 订单永久不可结算），但 ChatGPT 的“资金锁定”表述说重了——锁定资金可通过 releaseOrderLock / 硬撤单释放，非永久损失。故优先级排在治理之后，主网前关闭即可。
- 调研项：Permit2 式无序 bitmap 的具体形态；对 EIP-712 订单结构的影响（nonce 字段保留、消费语义变更）、前端 fetchOrderNonce 改法、订单规范文档与三方（前端/中继/合约）摘要一致性回归；存量订单过渡（测试网可直接切，主网未上线无包袱）。
- 同轮评估 Settlement 换 OZ EIP712 / ECDSA+SignatureChecker：摘要是三方冻结规范，换实现必须字节等价并用既有向量全量回归；既然本轮反正要动签名域，在此一并评估，避免两次动签名。

## 主网门槛轮（并入上线计划，不单开轮）

- **Vault 权限**（P1-04）：owner 迁 Safe 多签 + Timelock（基线已在差距清单：≥3 签名者、≥50%、硬件、48h 时间锁）；setSettlement 改延迟生效 + 事件告警 + 退出窗口；紧急暂停与用户安全退出演练并入既有的回滚/退出演练门槛。**决策点（Ren）**：多签签名者构成——主网上线部署时用 Ren 本人钱包体系组建，本方案不预设人选。
- **MCP 主网形态**（P1-06）：服务端持钥仅限测试网脚手架（既定）；主网形态 = 用户自持钱包签名 / 每 agent 独立钱包，签名接口已预留可替换层——随主网第一波的钱包方案定，不在本方案排期。
- **资产准入策略**（P2-06）：自助上架（展示/挂单）与**结算准入**分开：主网第一波结算只放行经核验的主流资产（白名单收口）；带税/rebase/黑名单类代币的逐项验证清单与自助结算开放条件后议。与知情选择规则合并设计：风险展示照旧，准入是另一道闸。**决策点（Ren）**：第一波白名单范围。
- **失败 gas 追偿**（P2-04）：主网保持关闭（与 ChatGPT 建议一致、与现配置一致）；若将来启用，先补可验证失败证据机制再议。
- **第三方审计**：合约与资金流独立审计列入主网预算项，Critical/High 全关才过门 #5。**决策点（Ren）**：预算与机构选择（花钱项）。
- **文档口径**（P2-08）：按 ChatGPT 专项核对结论写实——正常路径目标 50/50、受单方上限与价格可用性约束、短缺由气库吸收（本就是既定口径），补进 gas 规则文档，任一文档轮搭车。

## 签名撤单（未落锁订单）

ChatGPT 专项核对第 5 点：未落锁订单目前只能等过期。方案：中继侧签名撤单 + 墓碑（relay + 前端，不动合约；已落锁订单继续走现有硬撤单）。优先级在治理轮之后，排入下一中继相关轮或独立小轮，届时与 Nostr 镜像墓碑一并设计。
