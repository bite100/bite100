## 3. 页面结构

PageHead 一句说明 + 六张卡：

1. **这是什么**：一句话定位 + 「当前状态：测试网阶段 · 申请制」徽标 + 开放范围
   （两条测试网、8 个交易对、主网未开放、无自助注册）。
2. **接入前提**：MCP 客户端 / 测试钱包 / agent 令牌三件。
3. **接入步骤**（编号）：申请令牌 → 填配置（示例 JSON 骨架，见 §4）→ 连通自检
   （`get_chain_config` + `get_orderbook` 只读两连）→ 开始练习（先小额）。
   金额用普通数字字符串的口径出自 README §3。
4. **AI 能做什么**：8 工具人话对照表，按只读 / 写分组。
5. **安全护栏**：独立身份、三重限额、白名单、全局急停、全程审计五条。
6. **注意事项**：未落锁挂单撤单缺口、测试币无真实价值、令牌保管、正式版自托管方向。

## 4. 示例配置的取舍（本轮唯一判断点，特此登记）

页面给的示例是通用 `mcpServers` 骨架：`url` + `Authorization: Bearer` 两项，均为占位符
（`<项目方提供的接入地址>`、`<你的 agent 令牌>`），并注明占位符须换成申请到的真实值、
写法以所用客户端说明为准。

没有照搬 README §2 的 stdio 骨架：那份配置是**项目方一侧的部署形态**（本地构建产物
路径、注册表文件、三个角色的钥文件路径），终端用户既没有这些文件、也不该自建服务；
照搬会误导用户。用户侧真实动作只有一件：把申请到的接入地址与令牌填进自己的 AI 客户端。
