## 1. 设计 §2.1 载体定版（本轮核实结论）

设计 §2.1 留了「常设授权的执行载体」待核实。核实结果：**第一期载体 = 设置级常设授权 + 前端编排 + 本人钱包逐笔签名**，不改合约。

- 现有 Vault 只有 `withdraw(address token, uint256 amount)` 本人提款，**没有**委托/白名单提款面；要让 Vault 被第三方自动提款必须新写合约——与「原则上不动合约、只做集成」冲突，且第一期通道全是测试网，先不上。
- 因此常设授权 `standingAuth` 在第一期是**设置级开关**（设计 §2 决策 ③「全量开/关、随时可撤销」原文即此口径，§2.1 第 1 条自带退路）：开关 + 默认通道 + 披露确认齐备时，编排器自动生成交付记录并备好全部参数；**发起那一下**（从 Vault 提款、向桥存入）仍由用户在交付记录上点「发起交付」并在钱包里逐笔签名——钱包签名机制本身决定了前端不能代签。这与设计 §4.2「动作收敛为记录上的按钮，不新造独立进程」一致。
- 后续若上主网且量起来，再评估会话签名器/新合约载体，按设计 §2.1 的上行路径另轮立项。

## 2. 逐节对照设计文档的落地

| 设计小节 | 落地 |
|---|---|
| §1.1 先结算后交付 | 编排器只在成交已结算（本地链上成交历史 TradeStorage，源头是 Settlement 事件回填）后生成交付记录；交付是结算之后的独立动作，任何交付失败不回滚、不影响已结算成交 |
| §1.2 四级路由 | `decideRoute`（services/defaultBridge/support.ts）：无设置/同链/授权关 → 无动作；披露失效 → 挂起待确认；默认桥可用 → 默认通道；不支持 → 成交前问一次（`noFallbackPref='ask'`，出厂默认）或只在成交链（`settle-chain-only` 预设）。二级备选链不在第一期（§8 既定） |
| §1.3 交付费归属 | 披露文案与交付记录均写明：桥费由**接收方**（本笔收款人）从成交款承担，与结算 gas 五五完全分开；记录落 `feeNativeWei` 实际值 |
| §2.2 设置入口（三处） | 桥页顶部「我的默认通道」设置区（通道卡片→披露屏→勾选确认保存，可改选/重确认）；资产页入口行「跨链交付设置：默认通道 X / 未设置 ›」；「其他」页同名入口行（带当前设置摘要） |
| §2.3 披露材料（版本化） | `disclosures.ts`：三条通道各一份完整披露（费率结构/时效主网与测试网分开/安全模型/风险点/不可撤销/失败去向与三段失败指南），`version` 起始 1；确认记录 `{channel, disclosureVersion, confirmedAt}` 存设置里，文案升版后 `hasValidConfirmation` 自动判失效 → 在途规划转挂起、设置区出重新确认横幅。LayerZero 风险点含「目前只有 LayerZero 官方一家在验证，等于信任这一家」大白话 + KelpDAO 先例 |
| §2.4 资料复用 | 披露的时效/费率口径全部取自既有调研与第 9/16/19 轮实测（LZ 测试网 ≈458 秒、CCIP ≈20 分钟、Wormhole 约 59 分钟人工接力），费率只写结构不写死实时数字 |
| §2.5 使用说明 | 设置区顶部四段说明块（干什么/前提/步骤/注意事项）随功能同轮上线；交付记录区、资产页在途标注、下单票预估行各带就地说明 |
| §3 时效预期 | 一行预估与披露均按主网/测试网分开给时效；交付记录带发起/到账时间与超时阈值（按通道×环境，disclosures.ts 的 `timeoutMs`） |
| §4.1 资产范围 | 支持矩阵 `channelSupports` 按真实集成边界：**当前三桥真实可达资产只有 TKA**（LZ 原生 TKA、CCIP/Wormhole 经 wTKA）；资产须在成交链与主场链两侧都登记且目标链桥地址非零才算支持。USDT 等主流资产无消息桥通道 → 跨链成交规划为不支持（走 §6 三级/或等主网极速档），绝不假装可达 |
| §4.2 交付记录 | 挂订单历史（TradeTabsPanel）下方「跨链交付记录」区，不新建页面；字段：状态/通道/金额/实际桥费/追踪链接/发起与到账时间；资产页余额行对在途金额逐资产标注「其中交付在途 X（经 Y 送往 Z，未到账前不可用）」。§8 预留位：记录带 `executor: 'bridge'` 字段；`fallbackCredited` 只有平台垫付回款通道可置 true，**第一期前端永不置**（防与链上到账重复记账） |
| §5 边界检查 | relay/operator 面零触碰（relay diff 为空）；节点零触碰；推翻式重构为零——唯一重构是把桥页内嵌的三桥执行逻辑抽成 `services/bridgeExecutors.ts` 供桥页与编排器共用（骑同一实现，不是重写）；Soak/合成流量不替代真实验证（见 §6 偏差 4） |
| §6 三级与目录层 | 下单票（LimitOrderFormWidget，桌面+移动共用同一组件）渲染一行非阻塞预估（`estimate.ts`，按本单将收到的资产判定）；默认桥不支持且预设 ask 时，当场给临时通道选择（**只有已确认过该通道披露的才能点**，否则按钮禁用并提示先去设置区确认——选前必须有完整披露）与「只在成交链交付」两个一次性选项，选择经 `pushTempOverride` 落一次性授权、成交规划时消费一次。目录层：交易对切换器与行情列表对不可交付对标注「仅同链交易」（`pairSameChainOnly`：任一侧资产在全部通道都不可交付，如 BTC/USDT） |
| §7.1 编排与幂等 | `orchestrator.ts`：`planDelivery` 按 (tradeId, receiver) 幂等生成记录（重扫不重复）；金额按 Vault 实际可用额封顶（结算 gas 已从成交款扣减）；发起失败按阶段标注资金位置（提款前失败=钱在 Vault；提款后存入失败=钱在钱包、重试跳过提款步）。状态检测：LZ 查链上状态（delivered/failed），CCIP/Wormhole 第一期做超时检测 + 追踪链接（见偏差 2） |
| §7.2 状态机 | `deliveries.ts` 纯函数状态机 + 合法迁移表：not-needed / pending-decision / suspended-disclosure / ask-required / initiating / in-flight / delivered / anomaly；重试只允许从 anomaly 且 anomalyKind=initiation-failed 出发；`timeout` 与 `channel-failure-confirmed` 事件**不**触发任何回款记账 |
| §7.3 异常与三出口 | 异常记录逐笔带：失败指南（按通道×失败类型三段文案）、「重试交付」（仅发起失败）、「提取到钱包」（资金仍在 Vault 时）；无法自动恢复时记录明说资金确切位置（成交链 Vault 或本人钱包），不假装已处理。fallback 永远要用户显式动作，不静默 |
| §7.4 失败指南 | 三通道披露各含三段失败指南（发起失败/在途超时/目的链问题），在设置披露屏与异常记录两处同文案复用 |
| §8 数据模型预留 | `executor` 字段已建（第一期恒 'bridge'）；乐观到账/垫付档位字段（`fallbackCredited`）已预留且前端不置位 |
| §9 风险对照 | 静默换桥——路由判定与单测双重锁死（不支持→ask/none，永不产出别的通道）；披露过期仍执行——规划时逐笔校验确认版本；重复发起——(tradeId, receiver) 幂等 + 状态机迁移表；费用误解——披露与记录双处写明两笔账分开 |
| §10 验收 | ① 本地核验（单测+构建）本轮完成，数字见 §5；② ChatGPT 复核走推送后既定流程（主聊天）；③ 测试网真实小额全链路实测属主聊天核验阶段（见偏差 4），本轮不冒充 |

## 6. 与设计文档的偏差（全部如实登记）

1. **发起动作需用户点一次「发起交付」并逐笔钱包签名**，不是全自动无人值守发起。原因见 §1 载体定版：Vault 无委托提款面且钱包签名不可代签；设计 §2.1 第 1 条与 §4.2 已为此留口径（设置级开关 + 动作收敛为记录按钮）。记录生成、参数准备、状态跟踪全自动；钱的移动逐笔本人签名，量级与设计目标一致。
2. **CCIP/Wormhole 在途状态第一期只做超时检测 + 官方追踪链接**，LZ 做链上状态轮询。设计 §7.1 的到账检测本就列了多种可选方式；两家的消息状态 API 接入留待后续轮（WormholeScan/CCIP explorer 接口另行核实后再接，不猜接口）。
3. **资产支持矩阵第一期只有 TKA**。这是三桥当前真实集成的边界（设计 §4.1 以「确有通道」为准），不是收窄设计：USDT 等资产在任何消息桥上都没有已部署通道，规划层如实判不支持并走三级询问/成交链口径；主网极速档（LI.FI，待 key）上线后按同一矩阵扩列。
4. **§10 验收第 3 项（测试网真实小额全链路实测）未在本轮执行**：本轮在本地分支只做代码、单测与构建门禁，未部署站点、未发真实交易；实测（设默认桥→跨链成交→自动交付到账→异常路径抽查）留主聊天核验阶段在合并/推送决策后进行，本轮不冒充已验证。
