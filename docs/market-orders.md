# 市价单设计（第十七轮 Part B）

> 决策背景：Ren 拍板走 Hyperliquid 路线——订单簿 + 市价单 + 做市金库、无自有 AMM
> （见 round-17 记录）。市价单是订单簿的第二个订单类型，与限价单共用同一条
> 签名、锁定、撮合、结算管线。本文是实现前的设计定稿；实现与本文不一致处以
> round-17 记录的偏离说明为准。

## 1. 核心设计：不改签名结构，执行指令走订单消息字段

首选设计经代码核实**成立**，不做替代：

- 市价单在签名层就是一张**限价单**：用户签的 EIP-712 订单与限价单完全同构，
  其中 `price` 字段即**保护价**（买入的最高可接受价 / 卖出的最低可接受价）。
  EIP-712 结构、签名域、Settlement 合约、Vault 锁定**全部零改动，无需重部署**。
- 「按市价立即执行」的意图通过订单消息（`storage.Order` 的 JSON 表示）上的
  `execType` 字段传递：`execType: "market"`；缺省或 `"limit"` 为限价单。
  该字段**不进签名**（`BuildSignedOrder` 不读取它），随订单经 API 与 gossip
  广播，各节点处理一致。
- 为什么未签名的执行指令不构成伪造面：它只能影响**订单本人**的执行方式，
  且一切执行都被签名内的保护价与数量封顶——
  - 把别人的限价单改标 `market`：最坏结果是该订单以其**自己签的限价**为
    保护价被立即成交（价格不劣于其签名授权），余量取消而不是继续挂单；
  - 把市价单的标记抹掉：订单退化为以保护价挂单的限价单，仍在其签名授权内；
  - 价格、数量、交易者、nonce 都在签名内，指令字段改不动任何一项。
  指令字段不签名与「撤单请求靠订单本身的签名鉴权」是同一信任模型。

## 2. 执行语义（IOC）

1. **入口拒绝**：市价单到达入口节点时，若本地订单簿对手盘为空，API 同步
   返回 400 并给出明确错误（`market order rejected: no liquidity on the
   opposite side of the book`），不广播、不落锁。
   说明：多节点网络中各节点盘口靠 gossip 收敛，入口节点的盘口视图是提交
   时刻的近似；即便某节点视图滞后，接单节点的 IOC 执行也只会产生
   「零成交 + 余量取消」的结果，不会产生错误成交。
2. **落锁**：与限价单同一路径——按保护价计算全额义务落锁（买：按保护价的
   `amountOut` 锁 quote；卖：`amountIn` 锁 base）。落锁失败（可用余额不足等）
   拒绝该订单，与限价单一致。
3. **撮合**：调用撮合引擎但**不先入簿**：从对手盘最优档起逐档成交，成交价
   一律为 maker 价（价格改善归 taker）；当下一档价格越过保护价（买：高于
   保护价；卖：低于保护价）立即停止。
4. **余量**：未成交部分**立即自动撤销、永不进订单簿**（IOC）。订单记录以
   最终状态落库：全额成交 `filled`；部分或零成交 `cancelled`（`filled`
   字段记实际成交量），前端「历史订单」可见。
5. **锁定释放**（与第十五轮的联动，含一条由合约接口推导出的硬约束）：
   - 已成交部分的锁定由 Settlement 结算时按笔消费（`consumeOrderLock`），
     与限价单无异；
   - 未成交部分的锁定必须释放，但 Vault 的 `releaseOrderLock` 释放的是该
     订单锁定的**全部剩余量**，且结算对 `remaining` 的消费是异步发生的——
     若在成交结算落链前就释放，会把已成交未结算的部分一并放掉，随后该笔
     结算将因锁定记录消失而 revert。因此释放时点被约束为：
     - **零成交**：无任何待结算成交，接单节点立即全额释放；
     - **有成交**：接单节点异步等待——轮询 Vault 的 `orderLocks(digest)`
       剩余量，待其恰好降至「应剩锁定量」时再调用 `releaseOrderLock`
       精确释放余量。应剩锁定量（锁定代币口径）= 锁定义务 − Σ 各笔成交
       的 `fill.AmountOut`（taker 在每笔 Fill 中恒付出 AmountOut）；它有
       两个来源，缺一不可：① 未成交数量对应的义务；② **买单的价格改善
       差额**（按保护价落锁、按 maker 价消费）——因此全额成交的买单同样
       可能留有余量需要释放，不能以「全额成交」为由跳过。等待有界（超时
       记日志放弃），订单到期后任何人可经 `releaseExpiredOrderLock` 释放，
       为硬兜底。
6. **结算**：成交生成的 Fill 与限价单成交完全同构（taker 签名订单即保护价
   限价单，累计成交量校验、按 maker 价成交的价格改善均为既有行为），
   Settlement 与 Vault 合约**无需任何改动**——由 anvil E2E 复证（见 §5）。

## 3. 前端语义

- 下单面板「订单类型」切换为真功能：限价 / 市价。
- 市价模式隐藏价格输入，代之以**滑点容忍**（%，默认 1%）：保护价由当前
  对手盘最优价自动推导——买入 = 最优卖价 × (1 + 滑点)，卖出 = 最优买价
  × (1 − 滑点)；面板展示推导出的保护价与按当前盘口逐档试算的**预估成交
  均价**、可成交量；盘口为空或深度不足时在面板内明示。
- 点击盘口某档价格时自动切回限价模式并带入该价格（盘口点击的语义是
  「按这个价下单」，属限价行为）。
- 市价单同样走 Part D 的 Vault 余额预检/补存：义务按保护价计算。
- 面板说明（随功能同轮上线）：市价单如何成交、保护价是什么、余量为何
  会被取消、锁定何时释放。

## 4. 与限价单的行为对照

| | 限价单 | 市价单 |
|---|---|---|
| 签名 | 限价签名 | 同构，price = 保护价 |
| 执行指令 | `execType` 缺省/`limit` | `execType: "market"`（未签名） |
| 入簿 | 未成交部分挂簿 | 永不入簿（IOC） |
| 成交价 | maker 价（不劣于限价） | maker 价（不劣于保护价） |
| 落锁 | 全额义务 | 全额义务（按保护价） |
| 余量锁定释放 | 撤单/到期时 | 零成交立即；有成交待结算消费后精确释放（§2.5） |
| 空盘口 | 正常挂簿 | 入口同步拒绝并报错 |

## 5. 验证

- Go 单元测试：撮合层 IOC 语义（逐档成交 / 部分成交余量不入簿 / 保护价
  止步 / 空盘口零成交 / 卖向对称）；API 层空盘口拒绝与字段校验；
  结算包 `ReleaseRemainderAfterSettlement` 的等待-释放逻辑由 anvil E2E 覆盖。
- anvil E2E：多档限价单挂簿并落锁 → 市价单打过去 → 逐档成交价正确 →
  结算全部成交 → 释放余量锁定 → 读回锁定额精确归零（taker 侧）；另含
  保护价止步用例（只吃第一档、余量取消、对应锁定释放）。
- forge：结算路径零改动，以既有 99 例全绿为凭（Part A 后基线）。
